# 本机缠论图表

本应用在浏览器中选择 A 股股票或指数、周期与日期范围，显示 K 线、笔、线段、中枢、买卖点和 MACD。仅监听 `127.0.0.1:8765`，供个人本机使用。

## 安装和运行

在仓库根目录执行：

```bash
pyenv local 3.12.8
python -m venv .venv
.venv/bin/python -m pip install -r Script/requirements-web.txt
npm --prefix web/frontend ci
npm --prefix web/frontend run build
./start_web.sh
```

脚本会从仓库根目录启动本机 HTTP 服务；从其他目录调用也可以。只启动 API 时前端构建可省略，脚本会提示首页尚未构建。

打开 <http://127.0.0.1:8765/>。代码开发时，可同时运行 `npm --prefix web/frontend run dev`，Vite 会把 `/api` 请求代理到本机 Python 服务。

## 快速选择

图表区域随页面宽度展开，默认显示当前已加载的全部 K 线。可用图表右上角加减按钮或底部滑块缩放显示范围；切换图层保留当前缩放范围。

成功生成图表后，页面会在当前浏览器保留最近分析的 10 个标的；清除当前选择或刷新页面后，可直接点击“最近分析”中的标的重新选择。这个列表保存在浏览器本地存储，与 SQLite 行情缓存分开。日期栏提供“最近 30 天”“最近 1 季度”“最近 1 年”快捷项，以上海当天为终点；如数据源有确定的起止边界，日期会截取到该范围；点击快捷项只填写日期，仍需点击“分析图表”请求数据。

## 数据与限制

- 页面仅选择 `30m` 或 `1d`，优先默认 `30m`（只支持日线的标的默认 `1d`）。选 `30m` 时自上而下显示 `5m / 30m / 1d`，选 `1d` 时显示 `30m / 1d / 1w`。每张图独立加载和缩放，图层开关统一控制三张图；不支持或获取失败的周期单独提示，不影响其他图。
- 日期输入用于所选周期。相邻周期沿用结束日期，按交易时长比例调整包含首尾日期的天数：`5m → 30m` 为 6 倍、`30m → 1d` 为 8 倍、`1d → 1w` 为 5 倍；低级别相应缩短，最少一天。相邻图会裁剪到数据源已知可用范围，因此实际结束日期可能提前。节假日及历史数据限制会使实际 K 线数量有所不同。
- 如果获取行情后才发现历史起点晚于辅助图的请求起点，辅助图会按后端返回的实际开始日期自动缩短范围并重试一次，成功后显示调整提示。所选周期仍保留用户指定日期；没有明确可用起点或重试失败时，显示原有错误，不循环重试。

- 股票、ETF 的历史 5m/30m/日线/周线及指数历史日线/周线优先使用 BaoStock；指数 30m 使用新浪，LOF 日线使用新浪 LOF 接口。AkShare 适配器已注册，但不做失败后自动切换。
- 结束日期包含今天且选择不复权时，股票、ETF、指数使用新浪分钟行情补充盘中尾部。5m、30m 分别取对应周期；当天日线由完整的当日 30m 序列（含正在形成的末根）汇总，当前周线由日线汇总。日线窗口若从半天开始或中途缺柱，不会当成完整日线。旧的同周期历史柱优先保留，只有在重叠区间价格一致时才追加较新的数据；无重叠或价格不一致会保留历史并提示延迟。前后复权继续使用历史源并明确显示延迟，避免与不复权盘中价格混合。
- 未收盘柱参与暂定分析，以淡色和“未收盘”标记显示；页面显示取数时间、数据状态以及结构/买卖点可能变化的提示。缓存中的未收盘柱不会仅因时间经过而变成已收盘，必须获取收盘后的数据。仍需手动点击“分析图表”，没有自动轮询。
- 单次最多分析 5000 根 K 线。时间按 `Asia/Shanghai` 显示，分析结果中的首末时间来自实际返回的 K 线。
- 数据源可能因网络、限流或供应商接口变化失败。遇到 `SOURCE_TIMEOUT` 可稍后重试；`DATE_RANGE_UNAVAILABLE` 可缩短日期范围；`UNSUPPORTED_PERIOD` 应改选页面提供的周期。

## 本地行情缓存

网页分析把原始 K 线保存到仓库根目录的 `data/market.sqlite3`，该目录不会提交到 Git。已有数据库自动补充历史获取时间字段，不需要清空缓存。历史数据按数据源、标的、周期和复权方式区分；缺失区间才补取，向后扩展时重取交界处两天。最近三天的已缓存历史只在距上次获取至少 6 小时后按需校准。当前未完成交易日/周不写入已覆盖历史范围。

新浪盘中数据单独保存在 `live_snapshots` 中，按标的和分钟周期复用。首次请求最多 1970 根；后续默认取尾部 32 根，按间隔时间适当增加，最多 1970 根。如果尾部不能衔接，则重新请求完整近期窗口；仍无法衔接时明确提示，不静默跨越缺口。每次更新按时间去重覆盖尚在变化的柱，已观察到的较早数据继续保留；原来缓存中的指数历史也会参与合并。

同一后端进程中的新浪请求串行执行，实际网络调用间隔至少 2 秒；同一标的/分钟周期盘中 30 秒内复用，30m、日线和周线共享同一份 30m 快照。非交易时段冷却延长为 1 小时；跨过午休或收盘边界后首次查看会刷新一次收盘结果。失败按 60、120、240 秒递增退避，最长 15 分钟，有旧快照时展示旧数据并提示延迟。历史行情实际调用也按来源串行、至少间隔 2 秒，同一标的/周期失败后退避。上述设置是本应用的降频策略，不代表数据源承诺的额度或延迟；多服务进程不共享进程内锁。

标的目录也保存在同一个数据库，首次完整获取，超过一天时先用缓存、后台更新。缠论结构和指标每次重新计算，不保存分析结果。

删除 `data/market.sqlite3` 后，下次分析会重新获取行情。复权数据若因后续分红送转导致较早历史价格整体变化，也可删除此文件以强制全量刷新。

## 验证

```bash
.venv/bin/python -m pytest tests/web -q
npm --prefix web/frontend run test:unit -- --run
npm --prefix web/frontend run build
npm --prefix web/frontend exec -- playwright install chromium
npm --prefix web/frontend run test:e2e
```

端到端测试使用固定模拟行情，不依赖行情供应商。实际行情请在本机运行后用短日期范围手动确认。

BaoStock 股票使用标的上市日期作为最早可选日期；AkShare 和指数没有可靠的通用历史边界时，能力接口中的日期边界可能为空。分析时会核对交易日历：如果首根 K 线前已有应该出现的交易周期，会返回 `DATE_RANGE_UNAVAILABLE`，避免把上市前历史静默截成局部数据；休市日或同一周/月内的正常首根 K 线仍可使用。
